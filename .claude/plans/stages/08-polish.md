## Разделение ответственности и решения

### 404 и `errorElement` — два независимых механизма

`pages/not-found` — обычный дочерний маршрут (`path: "*"`), а не
срабатывание `errorElement`: несуществующий путь — не ошибка, а штатная
навигация, header должен остаться на экране. `RouteErrorBoundary`
(`app/router`) — `errorElement`, ловит непредвиденные ошибки рендера
внутри дерева страниц через `useRouteError()`/`isRouteErrorResponse()`.

**Найдено на первом ревью code-reviewer, [важно]:** `errorElement`
изначально висел на том же route-объекте, что и `element: <RootLayout
/>`. При ошибке рендера любой страницы React Router заменяет **весь**
элемент маршрута целиком — Header и навигация пропадали вместе с
содержимым, в отличие от 404-страницы, которая header сохраняет (это
обычный дочерний маршрут). Исправлено: `errorElement` вынесен на
отдельный вложенный route-объект внутри `children` у `RootLayout`, без
собственного `element` — по умолчанию такой маршрут рендерит `<Outlet
/>` (штатное поведение react-router, а не самодельное). Дерево:

```
{ element: <RootLayout />, children: [
  { errorElement: <RouteErrorBoundary />, children: [
    { path: search|movie|collection, element: ... },
    { path: "*", element: <NotFoundPage /> },
  ]},
]}
```

Закреплено тестом: `route-error-boundary.test.tsx` строит ту же форму
дерева с реально бросающим компонентом и проверяет, что layout-обёртка
(`<header>`) остаётся на экране при ошибке дочернего маршрута —
воспроизводит именно тот сценарий, что был найден на ревью.

### Скелетоны

`Spinner` удалён целиком (не использовался нигде после замены) —
`MovieCardSkeleton` (`shared/ui`) заменяет его в `widgets/movie-grid`
при `isLoading` (константа `SKELETON_CARD_COUNT = 8` в
`widgets/movie-grid/config` — число карточек-заглушек, визуальное
решение, не завязано на лимиты API), `MovieDetailsSkeleton` — в
`pages/movie` при `isFetching`. Обе заглушки декоративны
(`aria-hidden="true"` на самих карточках) — семантику загрузки несёт
обёртка вызывающего компонента, а не каждая отдельная карточка.

### Доступность

- `:focus-visible` — глобально в `app/styles/index.css`, до этого
  фокуса не было видно ни у одного интерактивного элемента.
- `aria-live="polite"` на общей обёртке `widgets/movie-grid` — один
  живой регион на все состояния (загрузка/ошибка/пусто/данные), чтобы
  скринридер объявлял смену результатов поиска.

  **Найдено на первом ревью, [мелочь]:** внутри уже была вложенная
  live-region — `role="status"` на контейнере скелетонов (свой
  неявный `aria-live="polite"`), задублированная с внешней обёрткой.
  Исправлено: `role="status"` убран, текст «Загрузка…» остался как
  visually-hidden `span` внутри общей `aria-live`-обёртки (тест
  `movie-grid.test.tsx` обновлён на `getByText("Загрузка…")` вместо
  `getByRole("status")`). `MovieDetailsSkeleton` в `pages/movie` не
  затронут — там `role="status"` не дублирует ничего, единственная
  живая область на странице.
- `lang="ru"` в `index.html` — интерфейс целиком на русском, был
  `lang="en"` от шаблона Vite.
- `useDocumentTitle` (`shared/lib`) — `document.title` через
  `useEffect`, суффикс `Watchpile` вынесен в константу.
  Подключён на всех страницах: `pages/search` → «Поиск фильмов»,
  `pages/collection` → «Коллекция», `pages/not-found` → «Страница не
  найдена», `pages/movie` → название фильма или «Фильм»/«Фильм не
  найден».

  **Найдено на первом ревью, [мелочь]:** на странице фильма заголовок
  вкладки при 404/невалидном id показывал общее «Фильм», хотя на
  экране «Фильм не найден» — расхождение заголовка и содержимого.
  Исправлено: условие «фильм не найден» (невалидный id, 404 от API,
  отсутствие данных) вычисляется один раз в переменной
  `isMovieNotFound` и переиспользуется и в `useDocumentTitle`, и в
  ветке рендера ошибки — вместо дублирования условия в двух местах.
  Закреплено тестами на `document.title` в `movie-page.test.tsx` (404
  и невалидный id).

  **Найдено на повторном ревью, [мелочь]:** после фикса константа
  называлась `LOADING_TITLE`, хотя использовалась не только на время
  загрузки, но и как фолбэк для не-404 ошибок — вводило в заблуждение.
  Переименована в `DEFAULT_MOVIE_TITLE`.

## Ручная проверка

`pnpm dev` + одноразовый Playwright-скрипт (не сохранён в репозитории —
не входит в `pnpm test`/CI, только для этой проверки, по аналогии с
`scripts/screenshot.mjs`, но с интерактивными действиями):

- переход на несуществующий путь → «Страница не найдена» + рабочая
  ссылка «Искать фильмы», header (навигация «Поиск»/«Коллекция») на
  месте;
- `<title>` вкладки меняется на `/` («Поиск фильмов · Watchpile»),
  `/collection` («Коллекция · Watchpile»);
- Tab-навигация — второй `Tab` фокусирует ссылку, `outline: 2px solid
  rgb(170, 59, 255)` (`var(--accent)`) виден;
- поиск с искусственно задержанным (через `page.route`) ответом API
  показывает сетку из 8 карточек-скелетонов с visually-hidden текстом
  «Загрузка…», которая заменяется реальными карточками (10 штук) после
  ответа.

Все проверки — до второго прохода правок по ревью; сами правки
(вынос `errorElement`, снятие дублирующего `role="status"`, заголовок
вкладки при 404) не меняют наблюдаемое поведение из пп. выше, кроме
целевых сценариев, которые закрыты тестами (см. «Тесты»).
